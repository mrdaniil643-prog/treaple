# Склад Treaple · самостоятельная версия

Приложение без сервера: статическая страница плюс Supabase (Postgres, вход по
почте и паролю, права на уровне строк). Регистрируется кто угодно, данные
магазинов разделены самой базой.

Всё ниже делается с телефона через Safari. Времени — минут пятнадцать.

## 1. База

1. Заведите бесплатный проект на [supabase.com](https://supabase.com).
   Запомните пароль базы, который он попросит придумать, — он пригодится
   только для прямого доступа, в приложении не используется.
2. Откройте **SQL Editor** → **New query**, вставьте целиком файл
   [`schema.sql`](schema.sql) и нажмите **Run**.
   Запрос создаёт таблицы, политики доступа и две функции для вступления в
   магазин. Повторный запуск безопасен.
3. **Project Settings → API Keys**: скопируйте **Project URL** и публичный
   ключ. Он называется **Publishable key** (`sb_publishable_...`) в новой
   панели или **anon public** (`eyJhbGci...`) в старой — годится любой,
   это один и тот же по смыслу ключ. Ключ **Secret** брать не нужно.

## 2. Страница

Впишите скопированное в [`config.js`](config.js):

```js
window.TREAPLE_CONFIG = {
  url:     "https://ваш-проект.supabase.co",
  anonKey: "eyJhbGciOi..."
};
```

Публичный ключ на то и публичный: прав он не даёт, доступ решают политики в
базе, поэтому он спокойно лежит в репозитории. **Ключ `secret` /
`service_role` сюда класть нельзя** — он обходит все политики.

Файл правится прямо на GitHub: откройте `app/config.js`, карандаш, Commit.

## 3. Публикация

**Settings → Pages → Source: Deploy from a branch**, ветка — ваша,
папка — `/ (root)`. Через минуту приложение открывается по адресу
`https://<логин>.github.io/treaple/app/`.

На айфоне: Safari → «Поделиться» → «На экран "Домой"». Дальше запускается
без адресной строки.

## 4. Куда ведут письма

Шаг, который легко пропустить и потом долго искать причину. По умолчанию
Supabase отправляет ссылки подтверждения почты и сброса пароля на
`http://localhost:3000` — то есть в никуда.

**Authentication → URL Configuration:**

- **Site URL** — адрес приложения:
  `https://mrdaniil643-prog.github.io/treaple/app/`
- **Redirect URLs** — добавьте туда же
  `https://mrdaniil643-prog.github.io/treaple/app/**`

Без этого регистрация пройдёт, но по ссылке из письма человек попадёт на
несуществующую страницу и решит, что всё сломано.

## 5. Себя — в администраторы

Зарегистрируйтесь в приложении. Затем в Supabase → SQL Editor:

```sql
insert into public.app_admins (user_id)
select id from auth.users order by created_at limit 1;
```

Запрос назначает администратором первого зарегистрировавшегося. Если вы
регистрировались не первым, подставьте свою почту:

```sql
insert into public.app_admins (user_id)
select id from auth.users where email = 'ваша@почта';
```

После этого в настройках приложения появится раздел **«Все магазины»**:
кто зарегистрировался, когда, в каком магазине и сколько у него позиций.

## Письма

Встроенный отправитель ограничен несколькими письмами в час — для проверки
это терпимо, для реальной работы подключите свой SMTP в
**Authentication → Emails**. Иначе на четвёртой регистрации письма просто
перестанут приходить, без внятной ошибки.

Если подтверждение мешает на старте, его можно выключить:
**Authentication → Sign In / Providers → Email → Confirm email**. Но помните,
что тогда любой зарегистрируется на чужую почту.

## Если приложение пишет «permission denied for table»

Значит роли `authenticated` не выданы права на таблицы. Выполните
[`grants.sql`](grants.sql) в SQL Editor — это отдельный короткий файл,
всю схему перезапускать не нужно.

Права на таблицу и права на строку — разные слои. `GRANT` решает, можно ли
обратиться к таблице вообще; RLS — какие строки вернутся. Без гранта
Postgres отвечает отказом, не доходя до политик, поэтому сообщение звучит
иначе, чем при отказе политики («new row violates row-level security
policy»).

## Что умеет приложение

**Список.** Остаток меняется прямо в карточке кнопками − и +: нажатия
применяются мгновенно, а в базу уходят одной записью через секунду после
последнего — так подряд идущая пересчётка не превращается в полсотни
запросов. Товар открывается нажатием на название. Заголовки категорий
липнут к верху, свёрнутые категории запоминаются между заходами. Внизу
списка — итог по тому, что сейчас на экране.

**Карточка товара.** Двусторонний расчёт: вводите закупку и наценку —
получаете цену продажи, или наоборот. Полоса под ценами показывает, какая
доля цены уходит на закупку, а какая остаётся. `Enter` сохраняет, `Esc`
закрывает. «Дубликат» заводит копию и сразу её открывает.

**Отмена вместо подтверждения.** Удаление товара и очистка склада
предлагают «Отменить» в подсказке снизу — это быстрее, чем отвечать
«точно?» на каждое удаление.

**Таблицы.** «Скачать CSV» отдаёт файл для Excel и Numbers (точка с запятой
и BOM — иначе Excel в русской локали ломает и колонки, и кириллицу).
«Загрузить CSV» читает файл обратно: разделитель определяется сам,
колонки — по названиям заголовков на русском или английском. Новые позиции
добавляются, знакомые (по названию и категории) обновляются. **Ничего не
удаляется:** файл может быть неполным.

**На компьютере.** `/` — поиск, `n` — новый товар, `Esc` в поиске —
очистить. Список и сводка показываются рядом.

**Магазин.** Управляющий переименовывает магазин прямо в настройках —
щёлкните по названию. «Сменить магазин» возвращает к выбору, не выходя из
учётной записи.

## Как устроен доступ

Разделение данных обеспечивает **Row Level Security** — правила выполняются
в базе на каждом запросе, а не в коде страницы. Подменить идентификатор
магазина в браузере бесполезно: база вернёт пустой ответ.

| Что | Кто видит | Кто меняет |
|---|---|---|
| Товары, журнал | участники магазина | участники магазина |
| Список участников | участники магазина | управляющий и сам участник |
| Магазин, код | участники магазина | управляющий |
| Все магазины и почты | администратор приложения | — |

Две тонкости, о которых стоит знать:

- **Роль не поднять себе самому.** Политика видит только новую строку и
  «сотрудник переписал себе role = owner» не поймала бы. Это ловит триггер
  `memberships_guard`, сравнивающий старое значение с новым.
- **Автора записи в журнале ставит сервер.** Если принимать имя от клиента,
  участник впишет в лог чужое — и журнал перестанет отвечать на вопрос, ради
  которого заведён. Имя подставляет триггер `events_stamp` по текущему
  пользователю. Журнал только дополняется: политик на изменение и удаление
  записей нет намеренно.
- **Код магазина перебираем.** Вступление идёт через функцию с правами
  владельца, и коды шестизначные — 64 миллиона сочетаний. Для магазина этого
  достаточно, но это не секрет: не считайте код защитой, считайте адресом.

## Что дальше

Приложение работает как есть. Если понадобится: пригласительные ссылки
вместо кодов, выгрузка по периодам, несколько складов внутри магазина,
история цен — всё это ложится на ту же схему.
