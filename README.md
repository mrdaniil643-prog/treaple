# treaple clipper

Нарезка длинных видео (подкасты, стримы, интервью) в вертикальные клипы
для YouTube Shorts, Reels и TikTok. Полностью локально, без платных API.

## Зачем именно клиппинг

Прямая монетизация коротких видео почти ничего не даёт: RPM на Shorts
порядка $0.03–0.10, у Reels шеринга рекламы нет вовсе. Миллион просмотров —
это $30–100. Поэтому клипы здесь не продукт, а источник трафика:

```
Shorts / Reels  →  Telegram-канал  →  бот  →  продукт за Stars
   (охват)          (аудитория)      (воронка)   (деньги)
```

Клиппинг выбран вместо AI-генерации осознанно: исходник — живая человеческая
речь, поэтому клипы не попадают под политику YouTube о неаутентичном
контенте, из-за которой штампованные AI-каналы теряют монетизацию.

## Без компьютера, одним ботом

Кидаете боту ссылку — получаете готовые клипы. Считает бесплатный раннер
GitHub Actions, слушает бесплатный Cloudflare Worker, телефон только
отправляет и загружает:

```
Telegram ──▶ Worker ──▶ GitHub Actions ──▶ Telegram ──▶ Shorts / Reels
             слушает    нарезает           клипы
```

Настройка целиком в браузере телефона: **[docs/bot.md](docs/bot.md)**.
Вариант без бота, кнопкой в Actions: [docs/iphone.md](docs/iphone.md).

## Установка


Нужен `ffmpeg` с `ffprobe` в PATH.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# Ubuntu/Debian
sudo apt-get install ffmpeg
# macOS
brew install ffmpeg
```

При первом запуске faster-whisper скачает модель с huggingface.co
(~500 МБ для `small`). Дальше всё работает офлайн.

## Быстрый старт

```bash
# всё сразу: скачать, расшифровать, отранжировать, нарезать
.venv/bin/python -m clipper run "https://www.youtube.com/watch?v=..."

# локальный файл тоже подойдёт
.venv/bin/python -m clipper run ~/videos/podcast.mp4 -n 8
```

Готовые клипы появятся в `out/<slug>/`: рядом с каждым `.mp4` лежит `.txt`
с заголовком, описанием и хештегами — для загрузки.

## Пошаговый режим

Расшифровка — самый долгий этап, поэтому она кешируется, и подбор клипов
можно крутить сколько угодно без пересчёта.

```bash
# 1. скачать + расшифровать + отранжировать, ничего не рендерить
python -m clipper analyze podcast.mp4 --explain

# 2. посмотреть кандидатов ещё раз (мгновенно, из кеша)
python -m clipper list work/podcast --top 30 --explain

# 3. отрендерить выбранное
python -m clipper clips work/podcast -n 10
```

## Второе мнение без затрат на API

Эвристики ранжируют неплохо, но вкус у них отсутствует. Можно добавить
ревью-проход, не платя за API: выгрузить кандидатов в JSON, оценить их в
Claude Code (или глазами), влить оценки обратно.

```bash
python -m clipper review-export work/podcast
# проставить llm_score / title в work/podcast/review.json
python -m clipper clips work/podcast --review work/podcast/review.json
```

Оценка ревью смешивается с эвристической в пропорции 60/40. Клипы без
оценки сохраняют исходный балл.

## Как отбираются клипы

Кандидаты строятся только по границам предложений — клип никогда не
начинается и не заканчивается посреди мысли. Каждый оценивается по восьми
признакам:

| Признак | Вес | Что ловит |
|---|---|---|
| `hook` | 0.26 | сильное начало: вопрос, «почему», «главная ошибка» |
| `standalone` | 0.20 | понятно без предыдущих 20 минут контекста |
| `closure` | 0.12 | мысль договорена до конца |
| `curiosity` | 0.14 | числа, проценты, превосходная степень |
| `duration` | 0.10 | колокол с центром на 34 секундах |
| `density` | 0.08 | 2–4 слова в секунду — живая речь |
| `energy` | 0.06 | динамика громкости, не монотонность |
| `confidence` | 0.04 | уверенность распознавания |

Самый тяжёлый штраф — за «висящее» начало: клип, открывающийся на «и»,
«но», «это», «поэтому», бросает зрителя в середину разговора.

## Кадрирование 16:9 → 9:16

| Режим | Что делает |
|---|---|
| `center` | фиксированный центральный кроп |
| `smart` | кроп встаёт туда, где движение и детали (по умолчанию) |
| `blur` | кадр целиком поверх размытой заливки, ничего не режется |

`smart` семплирует клип в низком разрешении, считает по колонкам движение
и детализацию, и ставит окно кропа на максимум. Если исходник уже
вертикальный, автоматически включается `blur`.

## Субтитры

Пословная подсветка, вжигается в кадр. Короткие видео смотрят без звука —
субтитры это не украшение, а основной канал. Шрифт, размер, цвета и
положение настраиваются в `[subtitles]`.

## Публикация

### В Telegram

```bash
export TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=...
python -m clipper publish telegram out/podcast
```

Зависимостей не требует — только стандартная библиотека. Токен берётся у
[@BotFather](https://t.me/BotFather), chat_id — из `getUpdates`. Лимит
загрузки для ботов 50 МБ; клип сверх лимита автоматически пережимается.

### На YouTube

```bash
python -m clipper publish youtube out/podcast --dry-run
python -m clipper publish youtube out/podcast --privacy unlisted
```

Требует `pip install google-api-python-client google-auth-oauthlib` и
OAuth-клиента типа Desktop app из Google Cloud Console (`client_secret.json`
в корне проекта), с включённым YouTube Data API v3.

**Про квоты.** Проекту даётся 10 000 единиц в сутки, один `videos.insert`
стоит 1 600 — это шесть загрузок в день, и обойти это нельзя. Под большие
объёмы нужно несколько проектов или запрос на увеличение квоты. Instagram
Graph API отдельно ограничивает 25 публикаций за 24 часа и требует
Business-аккаунт, связанный со страницей Facebook.

## Автоматизация

`.github/workflows/clip.yml` гоняет весь конвейер на раннере GitHub.
Запускается кнопкой в Actions или через `repository_dispatch` (например,
из iOS-команды по шерингу ссылки). Результат уходит в Telegram, если
заданы секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

Воркфлоу виден в интерфейсе, только если лежит в ветке по умолчанию.

## Конфигурация

```bash
cp config.example.toml config.toml
python -m clipper -c config.toml run podcast.mp4
```

Все параметры имеют рабочие значения по умолчанию, `config.toml` не
обязателен. Неизвестные ключи вызывают ошибку — опечатка в имени параметра
не пройдёт молча.

## Тесты

```bash
.venv/bin/python -m pytest tests/ -q
```

`tests/make_fixture.py` собирает детерминированный тестовый ролик
(синтетическая речь + объект, смещённый вправо) — на нём проверяется, что
`smart` кадрирует вправо, а не по центру.
