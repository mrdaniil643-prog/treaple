# МТ — музыкальный бар и караоке

Сайт с афишей, продажей билетов на конкретные столы (как в Яндекс Афише, только вместо кресел — столы), меню кухни и бара и кабинетом администратора.

## Запуск

Нужен Node.js 22.13 или новее. Внешних зависимостей нет: база — встроенный `node:sqlite`.

```bash
npm run dev        # разработка: демо-оплата, пароль админки печатается в консоль
npm test           # тесты бронирования и безопасности
ADMIN_TOKEN=длинный-случайный-пароль npm start   # боевой режим
```

`npm start` включает боевой режим: без `ADMIN_TOKEN` длиной от 12 символов сервер не запустится, а демо-оплата выключена — бронирование закрыто, пока не подключён эквайринг (или явно не задан `DEMO_PAYMENTS=1`).

| Переменная | Зачем |
| --- | --- |
| `ADMIN_TOKEN` | Пароль админки, от 12 символов. Сгенерировать: `node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"` |
| `PORT` | Порт, по умолчанию 3000 |
| `DB_FILE` | Файл базы, по умолчанию `data/mt.db` |
| `VENUE_TZ` | Часовой пояс заведения, по умолчанию `Europe/Moscow` |
| `TRUST_PROXY` | Сколько прокси стоит перед сервером (за nginx — `1`). Без этого все гости за прокси считаются одним IP |
| `PUBLIC_ORIGIN` | Адрес сайта, например `https://mt-bar.ru` — нужен, если прокси подменяет заголовок Host |
| `DEMO_PAYMENTS=1` | Включить демо-оплату в боевом режиме (только для показа) |
| `QR_SECRET` | Ключ подписи живых QR. Если не задан, создаётся случайный и хранится в базе |

## Страницы

| Адрес | Что там |
| --- | --- |
| `/` | Афиша, ближайшее событие, вход в меню |
| `/event?id=…` | Схема залов, выбор столов и мест, бронь и оплата |
| `/tickets` | «Мои билеты»: заказы с этого устройства и поиск по номеру заказа + телефону |
| `/ticket?t=…` | Один билет с QR-кодом — эту ссылку покупатель отправляет гостю |
| `/menu` | Меню кухни и барная карта с поиском |
| `/admin` | Продажи, схема занятости, возвраты, новые события, приглашения контролёров |
| `/staff` | Телефон контролёра: сканер, ввод кода для входа, последние проверки |
| `/c/…` | Сюда ведёт живой QR: у контролёра гасит билет, у остальных показывает «Это билет в МТ» |

## Как устроены билеты

**Билет = одно место за столом.** У каждого стола есть вместимость (`server/halls.js`). Гость выбирает стол на схеме и число мест — от одного до всех. В одном заказе можно взять несколько столов (до 20 мест).

- **Стол целиком.** Если за столом никого нет, его можно забрать весь — тогда к нему никого не подсадят. VIP-комната караоке (столы 34 и 35) продаётся только целиком.
- **Подсадка.** Если взята часть мест, остальные продаются другим гостям; на схеме такой стол подсвечен медным, на карточке видно, сколько мест уже занято.
- **Ценовые зоны.** Цена события — за место в обычной зоне; у сцены ×1,3, VIP ×1,6 (`ZONES`). Часть цены — депозит на меню, сумма задаётся в событии.

**Жизненный цикл заказа**

```
выбор столов ──► held (места закреплены на 10 минут) ──► paid ──► refunded
                     │                                    (возврат гостем за 24 ч или админом)
                     └─► expired / cancelled (места возвращаются в продажу)
```

Билеты внутри заказа: `held` → `active` → `used` (прошёл на входе), либо `released` / `cancelled`.

**Защита от двойной продажи.** Бронь проверяет свободные места и создаёт билеты в одной транзакции, а уникальный индекс `(событие, стол, место)` среди живых билетов не даст записать одно место дважды. Если пока гость выбирал, места заняли — он получает понятное сообщение, схема обновляется.

**Живая схема.** Страница события подписана на изменения через Server-Sent Events: когда кто-то бронирует стол, он мигает и меняет цвет у всех, кто смотрит схему.

**Отслеживание.**
- После оплаты заказ запоминается в браузере и доступен в «Мои билеты».
- С другого устройства заказ находится по номеру (`MT-XXXXXX`) и телефону.
- У каждого билета свой код и QR со ссылкой `/ticket?t=КОД`. Покупатель отправляет билеты друзьям и может подписать их именами гостей.
- На входе администратор сканирует QR камерой телефона (Chrome на Android) или вводит код. Повторный проход, билет на другое событие и возвращённый билет подсвечиваются.
- Каждое действие с билетом пишется в таблицу `ticket_log`.

## Вход гостей и контролёры

**Живой QR.** На билете QR и короткий код для входа меняются каждые 30 секунд: сервер подписывает код билета текущим 30-секундным интервалом (HMAC) и принимает подпись ещё один интервал. Скриншот перестаёт работать через минуту. Под QR идут часы и убывающая полоска — контролёр видит, что экран живой. Постоянный код билета на экране не показывается. Если пропала связь, билет честно пишет «Нет связи».

**Роль контролёра.** В админке в блоке «Контролёры» администратор создаёт приглашение с QR (одноразовое, действует 15 минут). Контролёр открывает его на своём телефоне — телефон получает защищённую cookie на 30 дней. Отключить телефон можно в админке или на самом телефоне. Контролёр не видит продажи, номера заказов и контакты гостей.

**Как проходит проверка**
1. Контролёр сканирует QR обычной камерой телефона. Ссылка `/c/<код>.<подпись>` открывается в браузере, и билет гасится сразу. Удобнее встроенный сканер на странице `/staff`: там после каждого скана звучит сигнал и не копятся вкладки.
2. Результат на весь экран: зелёный «Проходите» с именем и местом, красный «Уже прошёл в 21:14», «QR устарел», «Билет не на сегодня», «Событие отменено».
3. У гостя билет тут же меняется на «Прошёл 21:14» со штампом.
4. Посторонний, отсканировавший QR, видит только «Это билет в МТ» — без кода и данных.
5. Если QR не читается, контролёр вводит короткий код для входа (6 символов, тоже меняется). Если у гостя сел телефон, администратор находит заказ по имени и нажимает «Впустить гостя».

Гашение атомарное: при двух одновременных сканах пройдёт один. Каждый проход пишется в журнал с тем, кто и как пропустил.

## Оплата

В режиме разработки оплата демонстрационная: заказ подтверждается сразу (`pay` в `server/booking.js`). В боевом режиме бронь и оплата закрыты, пока не подключён эквайринг: создаём платёж при переходе к оплате и переводим заказ в `paid` только по вебхуку банка с проверкой подписи. Время брони (10 минут) покрывает оплату.

## Безопасность

- **Доступ к заказу.** Управлять заказом можно только по секретному токену (144 бита), который получает покупатель, либо по номеру заказа вместе с телефоном. Токен передаётся во фрагменте адреса (`/tickets#order=…`), поэтому не попадает в логи сервера и прокси.
- **Ссылка на билет** показывает гостю только его место: без номера заказа, контактов покупателя и кодов других билетов. Так один пересланный билет не даёт управлять всем заказом.
- **Коды.** Номер заказа — `MT-` и 8 символов, код билета — 12 символов; всё генерируется криптостойким `crypto.randomInt`.
- **Перебор.** Лимиты на IP для поиска заказа, брони, билетов и API. Вход в админку блокируется на 10 минут после 10 неверных паролей. Пароль сравнивается за постоянное время.
- **CSRF.** Изменяющие запросы принимаются только с собственного сайта (`Sec-Fetch-Site` / `Origin`) и только с `Content-Type: application/json`.
- **XSS.** Все пользовательские данные экранируются перед выводом. Content-Security-Policy запрещает сторонние и встроенные скрипты.
- **Заголовки.** `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy: no-referrer`, COOP/CORP, HSTS за HTTPS.
- **Сервер.** Отдаются только файлы из `public/` с известными расширениями, без скрытых файлов. Лимит тела запроса 64 КБ, таймауты медленных соединений, ограничение числа открытых потоков схемы.
- **Данные.** Весь SQL — подготовленные запросы. Текст от пользователей очищается от управляющих и невидимых символов, длина ограничена.

**Проверка.** В `.claude/skills/` установлены скиллы безопасности из [Claude-Code-CyberSecurity-Skill](https://github.com/Masriyan/Claude-Code-CyberSecurity-Skill) (MIT): `cyber-web-security`, `cyber-vulnerability-scanner`, `cyber-blue-team-defense`, `cyber-supply-chain-security`. Повторить проверку:

```bash
npm test                                                        # логика бронирования, QR, контролёры
npm run dev   # в другом окне, с ADMIN_TOKEN
ADMIN_TOKEN=... TARGET=http://localhost:3000 python3 scripts/security-check.py   # 64 атаки по OWASP Top 10
python3 .claude/skills/cyber-web-security/scripts/owasp_scanner.py --url http://localhost:3000
python3 .claude/skills/cyber-supply-chain-security/scripts/supply_chain_auditor.py --project-dir .
```

Перед запуском в работу: поставьте сайт за HTTPS (nginx или Caddy), задайте `ADMIN_TOKEN`, `TRUST_PROXY=1` и `PUBLIC_ORIGIN`, регулярно копируйте `data/mt.db` — в ней контакты гостей.
