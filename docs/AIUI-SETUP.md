# Подключение моста к AIUI Studio

## 1. Поднимите сервис на публичном HTTPS

AIUI ходит на внешний адрес, `localhost` не подойдёт. Для отладки хватит туннеля:

```bash
npm run dev
cloudflared tunnel --url http://localhost:8787   # или: ngrok http 8787
```

Итоговый URL вебхука: `https://<ваш-домен>/aiui/webhook`.

## 2. Настройте навык в AIUI Studio

1. Откройте приложение (`appid`), к которому привязаны очки.
2. Создайте кастомный навык (или включите постобработку семантики — что из этого
   доступно, зависит от вашего тарифа и версии платформы).
3. В качестве способа реализации выберите **webhook** и укажите URL из шага 1.
4. Добавьте заголовок с секретом, если платформа это позволяет:
   `x-webhook-token: <значение WEBHOOK_SECRET>`.
   Если умеет подписывать тело — оставьте HMAC-SHA256 в `x-aiui-signature`.
5. Таймаут вебхука поставьте заведомо больше `CLAUDE_TIMEOUT_MS` (по умолчанию 8 с).

## 3. Выберите формат ответа

Переменная `AIUI_RESPONSE_FORMAT`:

| Значение | Когда | Что отдаём |
|---|---|---|
| `skill` (по умолчанию) | кастомный навык / открытые вопросы | `{code: 0, message: "success", sid, data: {result: {answer}, answer: {type: "T", text}}}` |
| `postprocess` | постобработка семантики | исходное тело запроса + подменённый `answer: {type: "T", text}` |
| `plain` | свой клиент, без AIUI | `{sessionId, answer, markdown, chunks, codeBlocks, model, latencyMs}` |

Во всех форматах, кроме `plain`, рядом кладётся поле `claude` с полным ответом,
блоками кода и нарезкой под HUD. AIUI лишние поля игнорирует, а прошивка очков
или ваш клиент может их использовать.

## 4. Если формат не совпал

Точная схема запроса и ответа зависит от версии протокола AIUI (v2.0 / v2.1) и от
типа навыка, поэтому парсер сделан толерантным: текст запроса ищется по путям
`text`, `query`, `request.text`, `data.text`, `intent.text` и ещё нескольким,
идентификатор сессии — по `sid`, `sessionId`, `request.sid`, `deviceId`.

Если ваш вариант не распознан, сервис ответит `400` и залогирует ключи тела:

```json
{"level":"warn","msg":"Не нашёл текст запроса в теле вебхука","keys":["header","payload"]}
```

Допишите нужный путь в `TEXT_PATHS` / `SESSION_PATHS` в `src/aiui/protocol.ts`
(там же — `buildAiuiResponse`, если платформа ждёт другую форму ответа) и
добавьте случай в `test/protocol.test.ts`.

Быстрая проверка своего формата локально:

```bash
curl -s localhost:8787/aiui/webhook \
  -H 'content-type: application/json' \
  -H "x-webhook-token: $WEBHOOK_SECRET" \
  -d '{"header":{"sid":"s1"},"payload":{"text":"привет"}}' | jq
```

## 5. Проверка на очках

1. Разбудите очки штатным словом активации.
2. Задайте вопрос, который уходит в ваш навык.
3. Смотрите логи моста: на каждый ответ пишется строка
   `Ответ отдан в AIUI` с `sessionId`, `latencyMs`, длиной озвучки и числом блоков кода.

Если `latencyMs` подбирается к таймауту платформы — снижайте `CLAUDE_MAX_TOKENS`,
держите `CLAUDE_EFFORT=low` или переключитесь на `claude-haiku-4-5`.

## Ограничения

- Сервис не занимается ASR и TTS: и то и другое остаётся на стороне AIUI/очков.
- Память диалога живёт в процессе, при перезапуске теряется (см. README).
- Стриминг наружу отдаётся только на `/v1/chat/stream`; вебхук AIUI отвечает
  одним куском — это ограничение формата вебхука, а не модели.
