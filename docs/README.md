# Лендинг юридической практики

Статический сайт: HTML, CSS и ванильный JavaScript без сборки. Заявки уходят в Telegram
через одну serverless-функцию. Внешних зависимостей нет, шрифты лежат рядом с сайтом.

---

## Сначала прочитайте это

**Весь текст на сайте — рыба.** Имя юриста, реестровый номер, ИНН, адрес, телефон,
отзывы и цифры в блоке «Чем это подтверждается» придуманы как образец вёрстки.
Перед публикацией замените их на настоящие данные заказчика. Список ниже.

| Что заменить | Где |
|---|---|
| Имя, фамилия, «Савельев» в логотипе | `index.html`, поиск по `Савельев` |
| Реестровый номер, номер удостоверения, ИНН | секции `#lawyer` и футер |
| Телефон `+7 495 123-45-67` | `index.html` (6 мест) и `assets/js/main.js` (текст ошибки отправки) |
| Почта `hello@saveliev-legal.ru` | `index.html`, `assets/js/main.js` |
| Адрес и координаты карты | футер + `main.js`, параметр `ll=` в ссылке на Яндекс.Карты |
| Отзывы | секция `#reviews` |
| Фото юриста | `assets/img/lawyer.svg` → положите `lawyer.jpg` и поправьте `src` |
| Политика обработки ПДн | ссылка `#privacy` ведёт в никуда, подставьте реальный документ |

Публиковать отзывы доверителей без их согласия нельзя. Это ответственность
заказчика, не вёрстки.

## Структура

```
index.html              вся разметка, одна страница
.nojekyll               отключает Jekyll на GitHub Pages
assets/css/styles.css   токены темы → база → компоненты → моушен → адаптив
assets/js/main.js       анимации, слайдер, маска телефона, валидация, отправка
assets/fonts/           EB Garamond и Manrope, подмножества cyrillic + latin
assets/img/             favicon и заглушка портрета
api/lead.js             приём заявок, отправка в Telegram
vercel.json             кеш статики и заголовки безопасности
.env.example            какие переменные окружения нужны
```

## Локальный запуск

```bash
npm run dev          # python3 -m http.server 4173
# открыть http://127.0.0.1:4173
```

Форма при этом будет ругаться на отсутствующий `/api/lead`. Откройте
`http://127.0.0.1:4173/?demo=1`, чтобы посмотреть на успешную отправку без бэкенда,
или запустите `vercel dev` для проверки настоящей доставки в Telegram.

## Заявки в Telegram

1. Напишите [@BotFather](https://t.me/BotFather), команда `/newbot`. Получите токен
   вида `123456789:AA...`.
2. Создайте чат или группу, куда будут падать заявки, и добавьте туда бота.
3. Отправьте боту любое сообщение, затем откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьмите
   `result[0].message.chat.id`. У групп id отрицательный.
4. Задайте переменные окружения на хостинге:

```
TG_BOT_TOKEN=123456789:AA...
TG_CHAT_ID=-1001234567890
```

Токен читает только серверная функция. В браузер он не попадает, в репозиторий тоже:
`.env` лежит в `.gitignore`.

### Дублирование на почту

Опционально. Заведите ключ на [resend.com](https://resend.com) и добавьте:

```
RESEND_KEY=re_...
LEAD_EMAIL_TO=hello@example.ru
LEAD_EMAIL_FROM=site@example.ru
```

Если ключа нет, письма просто не отправляются, Telegram работает как обычно.
Отказ почты заявку не роняет.

### Что уже сделано против спама

- Скрытое поле-ловушка `company`: люди его не видят, боты заполняют. Такие заявки
  тихо отбрасываются с ответом 200, чтобы спамер не подбирал обход.
- Ограничение 3 заявки в минуту с одного IP.
- Проверка имени и 11 цифр телефона на сервере, а не только в браузере.
- Обрезка управляющих символов и экранирование HTML перед отправкой в Telegram.

Счётчик лимита живёт в памяти инстанса функции. Для одного адвокатского сайта
этого достаточно. Под нагрузкой замените на Upstash Redis или Vercel KV.

## Публикация

### Vercel (рекомендую, функция работает из коробки)

```bash
npm i -g vercel
vercel                      # первый деплой
vercel env add TG_BOT_TOKEN
vercel env add TG_CHAT_ID
vercel --prod
```

### Netlify

Перенесите `api/lead.js` в `netlify/functions/lead.js` и замените экспорт:

```js
export default async (req) => { /* тело функции */ }
```

В `netlify.toml` добавьте редирект `/api/lead` → `/.netlify/functions/lead`.

### GitHub Pages

Репозиторий публичный, поэтому Pages бесплатны. Папка называется `docs`, потому что
Pages умеет отдавать статику только из корня репозитория или из `docs/`.

Settings → Pages → Build and deployment → Source: **Deploy from a branch** →
ветка `claude/legal-site-animations-aj7zu1`, папка **/docs** → Save.
Через минуту сайт поднимется на `https://mrdaniil643-prog.github.io/treaple/`.

Файл `.nojekyll` рядом с `index.html` отключает Jekyll: без него Pages может
не отдать часть файлов из `assets`.

Serverless-функции на Pages нет, поэтому форма там работает в режиме превью
(см. ниже). Для приёма заявок нужен хостинг с функциями.

### Обычный хостинг без Node

Статику кладите как есть. Для формы поднимите функцию отдельно (Vercel, Cloud
Functions, любой PHP-скрипт с тем же контрактом) и пропишите адрес до загрузки
`main.js`:

```html
<script>window.LEAD_ENDPOINT = 'https://api.example.ru/lead'</script>
```

Ответ должен быть `200` с JSON-телом, иначе на сайте покажется ошибка.

### Режим превью формы

Там, где бэкенда нет, форма проходит валидацию и показывает успех, но заявку
никуда не отправляет. Режим включается тремя способами:

- домен оканчивается на `github.io`;
- в адресе есть `?demo=1`;
- до загрузки `main.js` задано `window.LEAD_ENDPOINT = 'demo'`.

На собственном домене клиента ни одно из условий не срабатывает, так что боевая
форма всегда идёт на реальный эндпоинт. Логика лежит в `main.js`, функция
`sendLead`. Если режим не нужен вовсе, удалите переменную `DEMO` и вызывайте
`fetch` напрямую.

## Как менять внешний вид

Вся тема собрана в блоке `:root` в начале `styles.css`. Цвета, шрифты, отступы,
скругления и тайминги анимаций лежат переменными. Хардкод-цветов в компонентах нет,
поэтому смена палитры — это правка десяти строк.

```css
--paper:#F1F2EF;   /* фон страницы */
--paper-2:#FFFFFF; /* карточки и панели форм */
--band:#E7E9E3;    /* чередующиеся полосы секций */
--ink:#15202E;     /* заголовки и основной текст */
--seal:#7B2C31;    /* единственный акцент: линии, цифры, главная кнопка */
--font-display:'EB Garamond', …   /* заголовки */
--font-text:'Manrope', …          /* текст */
```

Тема светлая: бумага, чернила и один акцент цвета сургучной печати. Поверхности
различаются светлотой, а не рамками и тенями. Тени не используются нигде.
Все три уровня текста (`--ink`, `--ink-2`, `--ink-3`) проходят WCAG AA и на бумаге,
и на полосе: это проверяет автотест. Если добавляете блок, берите готовую переменную,
а не новый цвет.

Тёмный здесь только футер. Это намеренная инверсия, которая закрывает лист снизу.

### Шрифты

EB Garamond для заголовков и Manrope для текста лежат в `assets/fonts` подмножествами
cyrillic и latin, вместе 107 КБ. Оба вариативные, вес 400–700. Внешних запросов к
Google Fonts нет, поэтому сайт не зависит от их доступности.

## Доступность и моушен

- Переходы 300–450 мс, `cubic-bezier(.22,1,.36,1)`. Анимируются только `transform`
  и `opacity`.
- `prefers-reduced-motion: reduce` отключает появления блоков и прорисовку подписи.
- Скролл-триггеры срабатывают один раз: при обратной прокрутке блоки не мигают.
- Без JavaScript страница читается полностью, FAQ раскрывается штатным `<details>`.
- Фокус виден на всех интерактивных элементах, тач-цели от 44 px, форма проходится
  с клавиатуры до отправки.
- Карта грузится по клику на заглушку: iframe Яндекса в первичной загрузке портит LCP.

## О текстах

Тексты написаны по правилам скилла `stop-slop`: без риторических вопросов в
заголовках, без конструкций «не X, а Y», без обрывочных фраз ради эффекта и без
наречий-усилителей. Если будете дописывать разделы, держите тот же тон: активный
залог, конкретика вместо оценок, обращение на «вы». Заголовок секции называет то,
о чём она, а не задаёт вопрос читателю.

## Автотесты

```bash
pip install playwright && playwright install chromium
python3 -m http.server 4173 &
python3 tests/e2e.py
```

Скрипт проверяет три брейкпоинта на горизонтальный скролл и ошибки в консоли, маску
телефона, валидацию, отправку обеих форм с подменой `/api/lead`, обязательное согласие
на обработку ПДн, FAQ, слайдер, поведение sticky-кнопки, режим reduced-motion и работу
страницы без JavaScript. Скриншоты кладёт в `shots/`.
