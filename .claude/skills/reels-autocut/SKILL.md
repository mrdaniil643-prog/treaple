# Нарезка длинного видео на рилсы

Один исходник → N самодостаточных вертикальных клипов. Пайплайн разбит на четыре
шага, каждый оставляет читаемый JSON, который можно править руками или агентом:

```
probe → transcribe → plan → render
исходник  транскрипт  что резать  готовые mp4
```

Скрипт: `scripts/autocut.py` (в папке этого навыка). Всё локально, API-ключи не нужны.

## Главное правило

**Не рендери, пока пользователь не увидел план.** Машинный отбор ошибается в вкусе,
а не в арифметике: границы фраз, длину и громкость он считает надёжно, а вот «какой
момент вообще стоит выкладывать» — решаете вы вдвоём. Поэтому порядок такой:
сначала `--plan-only`, потом показ плана, потом рендер.

## Быстрый старт

```bash
cd .claude/skills/reels-autocut/scripts

# 1. Всё до плана включительно
python3 autocut.py all /path/lecture.mp4 --outdir ~/reels/lecture \
        --lang ru --count 6 --plan-only

# 2. Посмотреть и поправить ~/reels/lecture/plan.json, затем
python3 autocut.py render --plan ~/reels/lecture/plan.json \
        --outdir ~/reels/lecture/clips --subs karaoke --style yellow-pop --uppercase
```

Без `--plan-only` команда `all` проходит весь путь и сразу отдаёт mp4 — так можно,
если пользователь явно сказал «просто нарежь, покажу потом».

## Что делает каждый шаг

### probe

```bash
python3 autocut.py probe source.mp4
```

Длительность, разрешение, fps, наличие звука, ориентация. Смотри на `orientation`:
если исходник уже `portrait`, кадрировать почти нечего — ставь `--reframe center`.
Если `has_audio: false`, субтитры и отбор по речи невозможны — предупреди пользователя
и режь по таймкодам, которые он назовёт сам.

### transcribe

```bash
python3 autocut.py transcribe source.mp4 --out out/transcript.json --lang ru --model small
python3 autocut.py transcribe source.mp4 --out out/transcript.json --import subs.srt
```

Локальный faster-whisper со словными таймкодами. Модели по возрастанию качества и
времени: `tiny`, `base`, `small`, `medium`, `large-v3`. `small` — рабочий компромисс
для часа записи; для интервью с плохим звуком бери `medium`.

Если faster-whisper не установлен или распознавание идёт слишком долго — `--import`
принимает готовый SRT/VTT (выгрузка из YouTube, Premiere, любого сервиса) и сам
раскладывает слова по времени внутри реплик.

### plan

```bash
python3 autocut.py plan --transcript out/transcript.json --out out/plan.json \
        --count 8 --min 20 --max 55 --sweet 34 --spread 0.06
```

Транскрипт режется на предложения (по пунктуации и по паузам), из них собираются все
окна допустимой длины, каждое получает оценку:

| Признак | Что означает | Вес |
|---|---|---|
| `hook` | первые секунды цепляют: вопрос, число, «главная ошибка», «как» | 0.30 |
| `payoff` | внутри есть конкретика: шаги, цифры, действие | 0.22 |
| `completeness` | начинается после паузы, заканчивается точкой, не с «это» и «поэтому» | 0.18 |
| `length` | близко к `--sweet` | 0.15 |
| `density` | темп речи около 3 слов в секунду | 0.15 |
| `filler_penalty` | «ну как бы», «типа», «короче» — штраф | −0.20 |

`--spread 0.05…0.15` растаскивает клипы по таймлайну, если все лучшие куски слиплись
в одном месте. В `plan.json` кроме `clips` лежит `shortlist` — 25 лучших кандидатов,
включая невыбранные: оттуда можно достать замену, не пересчитывая план.

### Твоя работа с планом

Эвристика отбирает механику, вкус — за тобой. Прочитай `plan.json` и:

1. **Проверь самодостаточность.** Клип начинается с «и вот поэтому» — сдвинь `start`
   на предыдущее предложение или возьми другой кандидат из `shortlist`.
2. **Проверь обрыв мысли.** Последняя фраза должна закрываться, а не повисать.
3. **Перепиши `title`** — он идёт в имя файла и в пакет публикации. Машина берёт
   первые восемь слов, это черновик.
4. **Выкинь лишнее.** Шесть слабых клипов хуже трёх сильных.
5. **Поставь `"approved": true`** тем, что идут в рендер, и запускай
   `render --approved-only`.

Показывай пользователю таблицу: id, тайминг, длина, первая фраза. Не вываливай весь
`plan.json` в чат.

### render

```bash
python3 autocut.py render --plan out/plan.json --outdir out/clips \
        --ratio 9:16 --fit crop --reframe track \
        --subs karaoke --style yellow-pop --uppercase --loudness -14
```

Собирает клипы, пишет `clips.json` с манифестом и кладёт рядом JPG-обложки.

`--dry-run` покажет, что будет отрендерено, и выйдет — полезно перед длинной пачкой.

## Ключи рендера

**Формат.** `--ratio 9:16` (Reels, Shorts, TikTok) · `4:5` (лента Instagram) ·
`1:1` · `16:9` · `source` (оставить как есть).

**Кадрирование `--fit`:**

- `crop` — вырезать вертикальный кусок из горизонтального кадра. Для говорящей головы.
- `blur` — вписать кадр целиком на размытый фон из него же. Для скринкастов,
  презентаций, таблиц — там, где обрезать нельзя, потеряется содержимое.
- `pad` — то же, но с чёрными полями.
- `stretch` — растянуть. Почти всегда плохо, есть для полноты.

**Проезд камеры `--reframe`** (только при `--fit crop`):

- `track` — кроп едет за субъектом. Детекция: сначала лица через OpenCV, если лиц
  мало — центроид движения (чистый Python, работает всегда), если и его нет — центр.
  Движение сглажено экспоненциально с мёртвой зоной, поэтому картину не качает.
- `static` — один кроп на клип по медиане положения субъекта. Спокойнее, надёжнее.
- `center` / `none` — центр кадра.

Если сборка ffmpeg не умеет `sendcmd`, рендер сам повторит попытку со статичным
кропом и скажет об этом. В `clips.json` поле `reframe` показывает, что реально вышло.

**Субтитры `--subs`:**

- `karaoke` — строка целиком, активное слово подсвечено. Универсальный вариант.
- `words` — по 1–2 слова крупно, как в TikTok. Держит внимание, но забирает кадр.
- `plain` — обычные блоки.
- `none`.

Стили `--style`: `bold-white`, `yellow-pop`, `mint`, `neon`, `clean-dark`.
`--uppercase` — капсом. `--font "Montserrat"` — **шрифт должен быть установлен
в системе**, иначе libass молча подставит свой и вид будет не тот; проверить
`fc-list | grep -i montserrat`. `--sub-scale 0.85` уменьшит кегль,
`--sub-margin 0.25` поднимет строку выше (доля высоты кадра от низа) — пригодится,
чтобы не попасть под интерфейс плеера.

**Звук.** `--loudness -14` — целевая громкость для Reels/TikTok/Shorts (LUFS).
`--loudness off` оставит исходную. Для YouTube привычнее `-14`, для подкастов `-16`.

**Качество.** `--crf 20` по умолчанию (меньше — лучше и тяжелее), `--preset veryfast`.
Для финальной выгрузки бери `--crf 18 --preset slow`, для черновика `--crf 28 --preset ultrafast`.

## Подводные камни

- **Пачка клипов рендерится последовательно.** Час исходника и восемь клипов — это
  минуты, не секунды. Скажи пользователю ожидаемое время, не молчи в процессе.
- **`--min`/`--max` определяют, найдётся ли вообще что-то.** Если скрипт ругается,
  что нет кусков нужной длины, — у человека короткие реплики, ослабь границы.
- **Субтитры проверяй глазами.** Распознавание путает термины, имена и англицизмы.
  Прогони `--keep-work`, открой `.work/*.ass`, поправь текст, перезапусти рендер.
- **Вертикальный кадр съедает края.** При `--fit crop` из 16:9 остаётся примерно
  треть ширины. Если в кадре два человека или важна графика — только `blur`.
- **Проверь первый клип перед пачкой.** `--only clip-01` быстрее, чем переделывать восемь.

## Что показать пользователю в конце

Таблицу из `clips.json`: имя файла, длительность, размер, первая фраза. Путь к папке.
И честно — что получилось хуже: где кадр обрезал лишнее, где субтитры спорные, где
клип стоит пересобрать. Молчаливая выдача восьми файлов — не результат.

## Дальше
